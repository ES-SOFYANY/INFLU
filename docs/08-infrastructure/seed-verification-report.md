## Fixes applied

### Fix #1 — CIN validation GSI mismatch (file: `docs/05-database/seed-data.json`)

**Problem** : the two `VALIDATION#CIN` items used `GSI5PK = STATUS#PENDING|VALIDATED`
while `apps/api/src/modules/admin-validation/admin-validation.repository.ts`
queries `IndexName: 'GSI1'` with `GSI1PK = ADMINVAL#CIN#<status>`. Result :
`GET /api/v1/admin/validations/cin` returned `items: []` even though the seed
included a PENDING CIN request for `kawtar.pending@example.ma`.

**Fix** : renamed both keys on the two items :

```diff
-          "GSI5PK": {"S": "STATUS#VALIDATED"},
-          "GSI5SK": {"S": "2026-02-16T09:00:00Z#u_creator_nano_010"}
+          "GSI1PK": {"S": "ADMINVAL#CIN#VALIDATED"},
+          "GSI1SK": {"S": "2026-02-16T09:00:00Z"}
```

```diff
-          "GSI5PK": {"S": "STATUS#PENDING"},
-          "GSI5SK": {"S": "2026-05-02T10:00:00Z#u_creator_pending_014"}
+          "GSI1PK": {"S": "ADMINVAL#CIN#PENDING"},
+          "GSI1SK": {"S": "2026-05-02T10:00:00Z"}
```

After `npm run db:seed -- --force`, `GET /admin/validations/cin` returns
**1 PENDING item (kawtar)** as expected by the spec.
